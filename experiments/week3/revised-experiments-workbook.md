# 3주차 진로 실험 — 수정 계획과 근거 초안

상태: 진행 중. 아래는 확인된 자료를 바탕으로 한 초안이며 개인 회고, 조사 결과, 실험 결과는 입력 전이다.

## PM — MOIMLOG 프로젝트 회고

- 배경과 목적(사용자 설명 및 MOIMLOG README): 순모임 녹음과 전사 내용을 검토하고 기존 순보고서 양식으로 정리하는 과정 지원.
- 사용자 보고: 본인이 기획·개발한 PM 경험. 개인의 구체적 판단, 역할과 결과는 확인 필요.
- README 기준 서비스 흐름: 녹음 → 전사 → 순장 검토 → 보고서 초안 및 DOCX.
- 문서상 미검증: 실제 한국어 전사와 장시간 음성, 동시 사용, 무료 한도, iOS 실기기. README의 iOS 관련 설명은 서로 상충하므로 실제 상태 추가 확인.
- 출처: https://github.com/itsjustcozyboy/MOIMLOG/blob/main/README.md
- 회고할 내용: 시작 계기, 실제 불편, 대안과 의사결정, 본인과 AI 역할, 어려움, 실현된 결과, 배움, 직무 적합성.
- 사전 기대는 회상으로 표시하며 점수는 사용자 입력 전 공란.

## Product Strategy — 기존 K-뷰티 프로젝트 사례

- 사용자 제공: 가천코코네스쿨 때부터 여름방학에 걸쳐 프로젝트 진행.
- 기존 AIM 자기보고 데이터: 시장 탐색, K-Beauty Buyer Sourcing AI Agent, AI 활용, 외부 프로젝트 및 실제 계약 경험.
- 대상 고객, 문제, 조사 근거, 선택한 전략, 실제 본인 기여, 계약 종류와 성과는 추가 확인이 필요하다.
- 출처: data/personal-career-dataset.yaml (자기보고).
- 사례 구성: 배경 → 시장·고객 문제 → 대안 및 근거 → 전략 선택 → 실행·계약 → 결과·한계 → 회고.
- 사전 기대는 회상이며 사후 평가는 사용자 직접 입력.

## HCI — 토스와 은행 앱 비교 실험

- 비교 대상: 토스 및 하나·KB국민·신한 은행 앱. 접근 가능한 실제 앱과 동일 과제 범위를 우선 확인한다.
- 공통 과제 후보: 계좌이체 진입, 거래내역 찾기, 이체 전 확인 정보 이해. 실제 송금은 수행하지 않는다.
- 공통 조건: 같은 OS, 앱 버전, 날짜, 로그인 상태, 화면 크기, 과제 시작점 기록. 앱별 계정 보유 여부와 기능 범위의 차이도 기록.
- 방법: 앱별 화면과 행동을 직접 관찰하여 과제별 단계·경로, 제공 정보, 오류 예방·피드백, 용어와 인지부담, 접근성을 비교.
- HCI 관점: 시각적 위계, 인지 부하, 일관성, 가시성, 오류 예방, 사용자 통제, 접근성. 원칙 적용은 분석자의 해석이며 실제 사용자의 어려움으로 단정하지 않는다.
- 사용자 테스트 가능 시 동의한 2~3명에게 동일 과제를 수행하게 하고 순서 효과, 선행 사용 경험, 힌트, 소요 시간과 결과를 기록. 소규모 편의표본을 일반화하지 않는다.
- 개인정보, 잔액, 계좌번호 등은 기록하지 않고 가상 데이터 사용. 비교 화면을 아직 확보하지 않았으므로 차이나 우열에 대한 결과는 없음.
- 결과물: 방법·비교표·스크린 근거(개인정보 제외)·개선안·한계·개인 회고.

## 공통 기록 및 다음 단계

- 사전: 예상 업무, 흥미, 난이도, 적합도. 과거 프로젝트의 사전 기대는 회상으로 표시.
- 사후: 흥미·몰입·난이도·적합도·진로 관심·재수행 의향 및 구체적 이유.
- 세 실험의 범위, 기존 경험, 시간과 AI 도움을 구분하고 점수만으로 순위를 단정하지 않는다.
- 사용자 회고와 HCI 직접 관찰, 비교 결과가 입력되기 전 실험 완료 처리 금지.
- 기존 AI PM 가설과 실제 PM 역할의 범위 차이, K-뷰티에서 확인된 전략업무의 범위, HCI 관찰과 연구 선호의 차이를 기록.
