# EX-W3-03 — HCI: 토스·은행 앱 탐색적 비교

상태: Agent의 공개 자료 탐색 수행; 네 앱의 동일 조건 실제 화면 관찰 및 사용자의 분석·평가는 미완료. 사람과 컴퓨터의 상호작용(HCI) 관점에서 정보 탐색과 행동 지원을 살펴본다. 이는 사용자 참여 사용성 테스트가 아니다. 연결 W2-H4의 연구 활동 일부만 다룬다.

## 질문과 공통 과제

같은 금융 업무에서 토스·하나원큐·KB스타뱅킹·신한 SOL뱅크는 정보를 찾고 이해하며 행동하도록 어떻게 설계되어 있는가?

과제 A: 로그인 후 앱 홈에서 가상의 계좌이체 진입점 찾기. 시작: 각 앱 홈; 종료: 실제 거래 없이 이체 입력 화면의 첫 단계 확인. 과제 B: 가상 이체의 최종 실행 직전 확인 정보에서 수취인·금액을 찾고 의미 설명. 시작: 동일한 가상 시나리오; 종료: 실행 전 확인 화면에서 중단. 실제 로그인 후 공통 화면이 확보되지 않아 A·B 모두 수행 결과 미확인이다. 실제 송금·가입 금지, 실제 계좌번호·잔액 수집 금지.

## 자료 조건과 관찰 — 2026-11-11

Agent가 웹에서 비로그인 공식 안내를 읽었다. 실기기·실제 앱 로그인 없음, 앱 버전·OS·화면 크기는 확인 불가. 아래는 제품의 실제 최신 화면을 동일 조건으로 관찰한 결과가 아니라 서로 다른 시점과 목적의 공식 안내 문구다.

| 앱 | 공개 자료에서 확인한 사실 | 과제 A/B의 직접 화면·조건 |
|---|---|---|
| 토스 | [송금 공식 안내](https://toss.im/service/easy-remittance)는 홈의 송금 버튼, 계좌번호 입력과 확인, 연락처 송금을 설명한다. 서비스 안내의 소요 시간은 광고 주장이지 측정값이 아니다. | 안내문만 확인; 현재 화면·버전·로그인 요건과 실제 단계 미확인. |
| 하나원큐 | [공식 서비스 안내 검색 결과](https://paxnet.hanabank.com/cont/smartapp/smartapp14/smartapp1401/index.jsp)에 조회·이체 서비스가 열거된다. 해당 본문은 직접 열기 시간 초과; 검색 인덱스에 의존한다. | 앱의 이체 진입점·확인 화면·버전·로그인 요건 미확인. |
| KB스타뱅킹 | [2025-05-22 공식 간편송금 안내](https://obank.kbstar.com/quics?articleClass=1&articleId=139299&bbsMode=view&boardId=669&compId=b058334&page=C020721&searchCondition=title&searchStr=&viewPage=3)는 로그인 화면의 ‘간편송금·결제’와 이체 화면의 ‘연락처이체’ 가입 진입을 설명한다. 당시 이용 가능 최소 버전을 명시한다. | 안내는 간편송금 가입 경로이지 일반 계좌이체 공통 과제의 관찰이 아님; 최신 화면과 실제 설치 버전·거래 확인 화면 미확인. |
| 신한 SOL뱅크 | [공식 체험 가이드](https://nsol.shinhan.com/contents/guide/)에 ‘계좌조회’와 ‘돈 보내기’ 메뉴가 있고 실제 거래가 발생하지 않는다고 설명한다. 페이지는 새로운 슈퍼SOL 가이드를 안내하므로 해당 SOL 자료의 현재성에 주의한다. | 가이드 목록만 확인; 체험 내부 단계·실제 앱 버전·로그인 조건과 확인 화면 미확인. |

## 평가 기준과 예비 해석

| 기준 | 현재 근거에 대한 해석 | 네 앱 비교 결론 |
|---|---|---|
| 가시성·시각적 위계 | 토스 안내는 홈 송금 진입을 설명하지만 실제 위치·시각 강조는 미관찰 | 미확인 |
| 메뉴·용어 이해 | 신한 안내의 ‘돈 보내기’, KB 안내의 ‘연락처이체’는 각 자료에 등장하는 표현; 서로 다른 화면과 기능이라 직접 우열 비교 불가 | 미확인 |
| 단계·인지 부담 | 안내에 제시된 설명은 실제 수행 단계 수가 아니다 | 미확인 |
| 일관성·피드백·오류 예방 | 최종 확인 정보나 오류 안내 화면이 없어 평가할 수 없다 | 미확인 |
| 사용자 통제·접근성 | 글자 크기·스크린리더·뒤로가기와 취소 동작을 실제 확인하지 못했다 | 미확인 |

## 개선 아이디어 — 검증 전 제안

1. 확인 화면에 수취인과 금액을 분명히 구분하고 실행 전 수정·취소 경로를 제공하는 공통 설계안을 실제 화면과 비교한다. **근거:** 금융 거래의 오류 예방이라는 HCI 원칙에 기반한 일반 제안; 특정 앱에 빠져 있다는 관찰은 없다.
2. 메뉴 진입에 일상어와 금융 용어를 함께 제시하는 방안을 검토한다. **근거:** 공개 안내에서 ‘돈 보내기’와 ‘이체’라는 다른 표현이 나타남. 어떤 표현이 실제 사용자를 더 잘 돕는지는 참여자 검증 전 미확인.

- [ ] 앱별 버전·관찰일·시작·종료점·단계·근거를 기록하고 개인정보를 제거; 관찰 사실과 해석을 분리
- [ ] 사용자 본인의 비교 판단·개선안과 AI 피드백 및 [사후 평가](evaluation.md) 기록
- [ ] 필요할 경우 참여자 2–3명에게 동의 후 동일 가상 과제 수행: 익명 ID, 과제, 행동·멈춤·힌트, 발언과 관찰자 해석을 별도 기록. 수행 전 금융 앱 경험, 수행 후 혼란 지점과 이해·안심 정도를 질문. 언제든 중단 가능하며 개인정보·실거래 금지.

참여자 모집·테스트는 미수행이다. 공개 안내는 홍보·가이드 자료라 최신 앱이나 실제 사용성을 대표하지 않으며, 서로 다른 버전·조건을 비교한 우열은 결론내릴 수 없다. 사용자 회고·점수·점수 이유: 미입력.
