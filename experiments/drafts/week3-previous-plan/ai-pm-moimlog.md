# EX-W3-01 — PM: MOIMLOG 기획과 개발 경험

상태: 진행 중 · 사용자의 기존 기획·개발 경험 확인 · 상세 과정과 평가는 미입력. 연결: 2주차 W2-H1 AI PM 가설에서 이어진 PM 직무 경험. 남은 정리 예상 2–3시간(잠정).

## 질문과 결과물
사용자가 제품 관리자(PM)로서 직접 기획·개발한 MOIMLOG를 실제 직무 경험으로 기록한다. 제품을 만들며 문제 정의, 방향 선택, 개발과 개선을 수행한 경험이 어땠는지 확인한다. 결과물: 실제 기획·개발 과정과 의사결정 기록, 필요시 제품 요구사항 문서(PRD).

## 확인된 맥락과 확인 수준
- 사용자 제공 목적: 대학부 순장의 녹음 → 전사 → 정리 → 순보고서 작성 지원.
- 사용자 직접 확인 (2026-11-11): MOIMLOG는 본인이 기획·개발한 프로젝트이며 PM으로서 수행한 경험이다. 상세 행동·개별 결정·시간·성과는 추가 확인한다.
- [MOIMLOG README](https://github.com/itsjustcozyboy/MOIMLOG/blob/main/README.md) 확인일 2026-11-11, GitHub 연결 도구. README는 웹 녹음·전사·검토·DOCX 출력, 외부 AI 전송 동의, 수동 검토 및 무료 사용 제한을 설명한다. 코드 실행·실제 동작을 독립 검증하지 않았다.
- README의 iOS 관련 이전 단락은 연결 미완료라고 쓰지만 마지막 단락은 흐름 구현을 주장한다. 최신 코드와 실제 기기 검증은 미확인. README는 Xcode 빌드·실기기 검증 미수행을 명시한다.
- README에 따르면 실제 한국어 전사 정확도, 동시 사용, 무료 한도와 전체 비용, 브라우저·접근성 검증은 추가 확인 필요. 기능별 현재 상태는 코드 및 사용자 설명으로 재확인한다.
- 사용자 개인의 세부 기여, 기존 결정과 결과는 미확인. README의 개별 구현 내용을 모두 본인이 직접 작성했다고 단정하지 않는다.

## 사전 평가
[공통 양식](evaluation.md): 미입력. 프로젝트가 이미 진행된 만큼 당시 기대를 회상해 기록하고, 수행 전 실시간 측정으로 소급하지 않는다.

## 진행 및 의사결정
1. 사용자가 직접 기획·개발한 과정과 제품 현황을 구체화한다.
2. 사용자·문제·현재 흐름과 사용상 마찰을 사용자와 구체화.
3. 기능 후보를 실제 상태 / 필요한 작업 / 확인 필요로 나누고 사용자가 우선순위 선택. 편의·개인정보·운영 비용·현실 사용 가능성을 함께 검토.
4. 선택 이유, 제외한 대안, 성공 기준과 검증 행동을 기록; 필요시 PRD 초안 작성.
5. 사용자 피드백과 사후 평가 기록. 외부 저장소 수정·배포 없음.

사용자 선택·근거·AI 피드백: 미입력. 성공 기준: 사용자와 함께 정의할 예정. 실제 수행 시간과 구체적 경험·성과: 미확인. 프로젝트 산출물: [MOIMLOG 저장소](https://github.com/itsjustcozyboy/MOIMLOG); 실험 기록과 회고는 미완료.

## 사후 평가 및 다음 행동
미완료. [공통 양식](evaluation.md) 사용. 직무 경험에 대한 해석은 사용자의 회고 이후 기록한다.
