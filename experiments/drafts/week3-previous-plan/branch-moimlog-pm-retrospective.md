# PM 직무 실험 — MOIMLOG 프로젝트 회고

상태: 사용자 자기보고에 기반한 회고 초안. 세부 기여·의사결정·성과와 사후 평가는 추가 확인 필요. 작성일: 2026-11-11.

## 시작 계기와 문제 정의

교회에서 순장(모임장)으로 섬기며 지체들의 삶 나눔과 말씀 나눔을 손으로 기록했다. 기록하는 동안 상대방의 이야기에 온전히 집중하기 어려웠고, 순장인 내가 이야기를 나눌 때는 다른 지체에게 대신 기록을 부탁해야 하는 불편이 있었다.

눈을 마주보며 대화할 수 있으면 서로의 이야기에 집중하고 공감하며 더 깊이 나누는 데 도움이 될 것이라는 나의 생각과, 기록 업무의 물리적인 불편을 함께 고려해 문제를 정의했다. 이는 사용자의 관점에서 세운 가설이며 별도 비교 연구로 효과를 검증한 결과는 아니다.

## 해결 방법과 MVP 경험

편의성을 높이기 위해 모임 기록과 보고서 작성 과정을 자동화하기로 했다. 초기 MVP에서는 네이버 클로바로 녹음·STT 전사를 수행하고 전사 내용을 ChatGPT에 전달해 정해진 순모임 양식에 맞는 DOCX를 만든 후, 내가 내용을 수정하여 실제 순모임 보고서를 완성해 보았다.

## 제품 개발과 계획

이후 위 과정을 웹 형태로 만들고 Groq API를 활용해 저렴한 비용으로 앱 형태까지 구현해 보았다. 약 5,000원은 목표 또는 예상 비용 수준으로 기록하며, 실제 월 총비용과 해당 금액의 산정 범위는 추가 확인한다.

2026년 12월까지 UI와 서비스를 완성해 App Store에 출시하는 것이 향후 계획이다. 출시와 실제 서비스 운영은 아직 완료된 성과로 기록하지 않는다.

MOIMLOG 저장소 README는 녹음·전사·검토·DOCX 흐름과 iOS 구현을 설명하지만 iOS 관련 서술에 상충하는 부분이 있다. 이 회고 작성 시점에 앱의 전체 기능을 직접 실행해 검증하지 않았다. 한국어 음성 정확도, 장시간 녹음, 동시 사용, 실제 무료 한도와 비용, 실기기 동작은 추가 확인한다.

## PM 경험으로서 검토할 내용

- 문제와 사용자 발견: 실제 순장으로서 경험한 기록 부담을 문제로 정의.
- 해결 방향: 기존 도구를 조합한 MVP에서 웹 및 앱 형태의 자동화로 발전.
- 제품 의사결정: 기능 우선순위와 대안 선택의 구체적인 이유는 사용자 추가 확인 필요.
- 개인 기여와 AI 역할: 구체적인 작업과 의사결정은 추가 확인 필요.
- 사용자 검증 및 효과: 본인이 보고서를 완성해 본 경험은 확인; 사용자 수, 시간 절약, 실제 사용과 만족도는 미확인.

- 당시의 기대: 이미 진행된 경험이므로 사전 평가는 회상으로 기록.
